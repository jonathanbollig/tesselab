# CLAUDE.md
For Claude Code sessions (and other developers) working on Tesselab: what the code does, how it is organized, the decisions and why, the pitfalls, how the user wants to work, and the state of the work. README.md is for users, `src/tesselab/AGENTS.md` is the module protocol.
## The project
Tesselab is a desktop viewer for scientific data whose analyses are small graphs of nodes, supplied by modules (Python, PySide6 + pyqtgraph). It grew out of the viewer of the author's own analysis package `kufner_uv_analysis` (private; five of its files are copied into the UV example, see below), which keeps working on its own and must not be changed by work here. The design was first worked out in a design document (v1 to v3); this code implements v3, and the places where it differs are listed below. Started 2026-11-20. A developer's private additions (machine paths, notes, test data) go into `CLAUDE.local.md`, which is not in git.
## How the user wants to work
Taken over from kufner_uv_analysis's CLAUDE.md, where they were learned:
- **Keep the code simple and readable.** No over-engineering; do what was asked, list further ideas as proposals.
- **Never change the physics silently.** The UV module must stay bit-identical to kufner_uv_analysis, where that package is installed (`tools/compare_uv.py`, `tests/test_uv_module.py`).
- **Real choices go to the user**, with options and a recommendation; visual choices with rendered screenshots.
- **Ask before changing the user's configuration** (conda environment, fish functions, settings). Tesselab runs from the source tree with `PYTHONPATH=src`, or after `pip install -e .`.
- **The user may be running a viewer.** Never stop processes by name, only by PID. Never write into the user's real data folders; work on copies.
- **Commits**: only when the user asks; one topic per commit; the subject says what changed, the body why and how it was checked.
- **Style**: plain English, short sentences, explain the why in docstrings; Markdown without hard wrapping and without blank lines around headings.

## Decisions, and why
- **Readers, compute nodes, views** (2026-11-24, the user: "Your suggestions are sound. Please implement", after a discussion of whether compute nodes need plots at all): only views (tesselab.View) have plots and interactions; readers (tesselab.Reader) read files, compute nodes compute; check refuses plots elsewhere. A view takes outputs of any stage as inputs; it is prepared in the window's process (Engine.prepare: its result holds its bound inputs, holds_inputs, nothing pickled to a worker; a source without a result leaves the input out with a warning instead of blocking) and is never offered as a source. Its draw functions read ctx.inputs and must be quick. Its interactions set its own parameters; bound to analysis variables they reach compute nodes (λ, ignored spectra, baseline, x axis in the UV module; chirp onsets, fit range, probe wavelength in TA; P.Points became bindable for that). Each view is a section of the card (views first, in view order); readers and compute nodes are folded under "Details" (open: their parameters), shown as plain groups when there is no view; their key results stand in the card's header. A view can be switched off in the graph (node entry "off", kept in the graph file): its section is hidden. A compute node can name default views (Node.views), added and connected with it. Reader and compute outputs get an automatic preview (preview.py) in the graph window's side panel, never in the card (the user's choice). In the graph the kinds are shaded (readers bluish, compute plain, views greenish: theme keys node_reader, node_view), views stand in the last column, the legend lists the shades. New protocol pieces: Toggle(param) with Points(keys=...), Lines(legend=False), Style symbol "_", and mark roles (Style(role=...): measured, fit, result, reference, unused, event; colors.MARKS gives their look per theme, a user's theme file changes them with [marks.<role>], a module's own fields win; the user agreed, 2026-11-24). The rig's records have a reader of their own (Rig records: steps.jsonl and config.json lie next to the power folder, so the power folder's fingerprint did not cover them). check accepts a reader that returns nothing when its file parameters are empty (an optional file the sample lacks). The graph window opens at a readable zoom (READABLE 0.85; a larger graph shows its top left), has scroll bars, and Ctrl+B folds its side panel (remembered).
- **Everything a node returns is data**: outputs are xarray Datasets, plots are descriptions (PlotSpec). So Tesselab can run nodes in worker processes, cache them, export every plot as JSON and PDF, number and link plots, and later draw with another library, without any module changing. Level 2 (own Qt widget) is the escape hatch; there is no direct pyqtgraph level (dropped in the design discussion: it would tie the protocol to pyqtgraph).
- **Fingerprints instead of invalidation, with early cutoff**: a result is stored under a hash of everything it depends on: node, module version and code hash, resolved parameters without redraw-only ones, file stamps, and the *content* of the data its inputs receive (a hash of each upstream output, NodeResult.output_hash). So a node whose input data stay the same is reused even when the node before it ran again (2026-11-21, after the user asked why everything was slow: dragging λ recomputed φ0(λ), which does not depend on λ; φ0(λ) is now its own UV node and is reused). A fingerprint can only be computed once the inputs have results; the runner and compute() walk the graph in dependency order. A result of an older state is never shown for the new one, but stays in memory (undo finds it again; engine.ResultMemory drops the least recently used beyond 1 GiB of outputs or 1000 results). Links between analyses are live: the linked output's content is part of the dependent's fingerprint, and the file stores `seen` (its content hash at the last save); a difference gives the warning "… has changed since this analysis was saved".
- **Worker processes are warmed** when a project opens (Runner.warm: every available module's nodes and numpy/xarray/pandas/scipy.interpolate/optimize imported in each worker); run_task reports importing the node's module (load_seconds) apart from the computation (seconds). Measured on 5_UC@2 with warm workers: spectra 86 ms, powers 81, steps 33, quantum yield 14, φ0(λ) 33.
- **Signature matching prefers names**: a variable with the signature's own name is taken first, shapes decide only where names do not fit. Found when the UV steps node took `end_time` as `absorbed_energy` (same shape); now in AGENTS.md. Only numeric variables match unless `numeric=False`. Both orientations of a matrix are offered.
- **Run-to-run identical UV results by construction**: each UV node calls the same IrradiationExperiment methods in the same order as load_data/calculate; datasets crossing process boundaries are pickled exactly. Verified bit-identical on all 71 real experiments (2026-11-20).
- **Analysis variables** (`vars`, parameters `{"var": name}`): one cursor moves every node bound to it (λ in the UV module: λ spectrum and both λ markers).
- **The project folder is the visible `tesselab/`** (it holds the user's work), recognized by `project.toml`. Paths in parameters are relative to the project, links to other analyses relative to `tesselab/` ("analyses/x.json#node.output").
- **Trust of project modules is stored in the user's config** (`~/.config/tesselab/trust.json`), never in the project (a project must not be able to declare itself trusted). The design doc said project.toml; this is the deliberate deviation.
- **Undo is snapshot-based** (Analysis.content() before each edit), merged while a cursor is dragged (coalesce key). Buttons in each card's header, left of the graph button (they act on that analysis; first in the rail, acting on the active card, moved there at the user's suggestion, 2026-11-23), and in the graph window's toolbar; usable only when there is a step. Redo is Ctrl+Shift+Z (the KDE/GNOME key, Qt's own in text fields on Linux) and Ctrl+Y (the Windows key; nothing else uses it). Undo/redo put the way back on the other list before telling anyone (card._restore), so whatever reacts to saved_changed sees both lists right.
- **An analysis can be open in several tabs** (2026-11-21, the user's choice; the kufner viewer allowed "7_GU (2x)"): its cards show the same in-memory analysis and share one undo history and saved state (card.Shared, Window.shared); an edit in one card appears in all; which groups are open is each card's own (the folds of the card changed last are saved). Opening it in the tab where it is already open just shows it. Two independent copies were rejected: their saves would overwrite each other.
- **Add node** connects inputs: the source of a node that takes the same kind of input (MCR next to SVD), else the output with matching variable names, else the latest; optional inputs stay unconnected.
- **The window's look** (2026-11-21, the user's review of the first version): the status dot in front of every header (card and group); unsaved changes shown by an orange save icon and amber tab text (a dot before the name was confused with the status dots); the zoom rectangle see-through; the tabs a strip of their own (Tabs: QTabBar + QStackedWidget, + right after the last tab; QTabWidget drew a black line); menu titles without & (KDE underlines mnemonics permanently); legends can go below the plot (legend="below", used by the power plot, where a legend in a corner covered data).
- **Rounded panels** (2026-11-22, the user: "make the rounded style consistent"): one radius scale in theme.py (PANEL_R 10 > CARD_R 8 > TILE_R 6 > CONTROL_R 5: inside a thing, less round than it), used by the style sheet and by everything painted. Chrome grey around two page-colored panels (the explorer paints its own; the tabs' page is the Tab scroll area with `border-radius` and viewport margins of PANEL_R at top and bottom, so scrolled content never covers the corners and disappears below a calm margin). Their tops are level with the tabs' tops (theme.GAP). The current tab flows into the page with concave feet, drawn by Tabs (the parent of strip and page) and reaching 2 px into the page: at scale 1.5 the boundary row is half covered by each widget, which showed a seam. Menus, tool tips, combo popups and the command palette are rounded: their windows get WA_TranslucentBackground when polished (theme._RoundPopups, an application event filter: ~2 µs per event). Combo boxes and check boxes are styled fully (arrow and check images from _icon_file). A dragged tab jumps to its new place once the mouse is over it (TabBar), instead of Qt's sliding movable tabs: the feet know only the tab's place and jumped while it slid (2026-11-23, the user's review).
- **The rail** (2026-11-23, the user's choice, as in the kufner viewer): no menu bar; a narrow column left of the explorer holds ☰ (every menu, in a QMenu; each action is also the window's own, or its shortcut would work only while the menu is open), the explorer's fold, open project, recent projects, save and save all. The window's top row is the tabs'; the first tab is indented so that its left foot stands on the page's straight top edge, past its round corner.
- **Card headers stay in view** (2026-11-22, the user: plots scrolled right up to the tabs): CardTop, from the kufner viewer: the header is a widget outside the card's layout (header_space keeps its place), placed by AnalysisCard.place_header on resize and scroll; pinned it draws the card's top itself.
- **The active card** (Ctrl+S, Ctrl+Z, export act on it) has an accent border; a click anywhere in a card (Window.eventFilter on the application: the card's children take the clicks) or focus in it makes it active; each tab remembers its own, switching tabs switches the active card (before, Ctrl+S could save a card of another tab).
- **Redraws keep unchanged marks** (2026-11-22, the user: dragging λ lagged more than in the kufner viewer): PanelView.set_marks compares each mark with the one drawn before at its place (_same_mark: kind, data, style) and keeps its items; a moved marker replaces one line instead of re-adding ~170 pyqtgraph items (~0.5 ms each). Legend and note only when they change; a linked analysis that already has the value does not redraw again; the cursor uses the newest position when the window is idle (a 0 ms timer, as in the kufner viewer) instead of at most every 80 ms. Measured with 5_UC@2 and 7_GU linked: ~190 ms → ~21 ms per λ step in the window's thread; the worker's quantum yield comes back in 3–9 ms.
- **Graph files** (2026-11-22, the user: "A graph defines an experiment analysis, that is most likely the same for a lot of experiments. Graph details should live there, sample details in the analysis file"): nodes, connections, variable bindings, the graph's parameter values and positions go to `tesselab/graphs/<name>.json`, shared by every analysis that names it; the analysis file keeps its sample: its own parameter values (`params`, only those it sets itself), variable values, links to other analyses, results, view. The user's choices: structure and layout in the graph file; an edit changes every analysis using the graph ("Use a separate copy" to split one off); graph values are defaults, an analysis's own values override them (accent dot in the forms; right-click: take the graph's value / make this the graph's). In memory an analysis stays whole (graph.merge), so engine, nodes and fingerprints are unchanged; graph.split takes it apart at save and after every edit (Analysis.push_graph), the other open analyses take the change over (pull_graph, Window.graph_changed). Own values: what a template fills in from the data (placeholders, graph.own_from_template), data paths, every value set in the analysis (set_own); a value changed but not marked counts as own too, so a sample's value never leaks into the graph. Undo steps are (content, graph before, graph after): a step that changed the graph puts it back only if no other analysis changed it since, else only this analysis's values go back. Templates make the project's graph file on first use (graphs/<template file>.json) and reuse it; analyses without "graph" (older files, no project) keep the graph inside, until "Share it in a graph file of its own". Unsaved = the sample changed or the graph file is dirty.
- **The graph window is the place to edit the graph** (2026-11-22, the user; it stays a pop-up: "gives space to the graph, can contain its own context menu, keeps the main window clean"): inputs, connections, adding and removing nodes, variables are edited there; the cards keep plots and parameters (each input as a read-only "from" line). A click selects (the inspector beside the canvas shows the node's inputs and parameters), double-click shows the node in the main window (a click used to scroll the card, which the user did not want). Boxes move on a 20 px grid (graph.GRID) and snap; the first move stores every position (in grid units, in the graph). No legend below any more: tooltips on ports, wires and boxes, a hint next to the mouse while dragging, a ? button with the keys. Own context menus everywhere (canvas: add, new variable, arrange, fit, graph file, undo; node: show, rename, duplicate, run, actions, inputs, bind/unbind; input port: its choices; wire: remove, which variable of the source; variable: value, rename, bind, remove). Drop a connection on empty space: a search for nodes that take it. Binding by dragging a variable onto a node offers only parameters of the same kind and unit.
- **What the graph shows** (2026-11-24, the user): variables are a table over the canvas's top right corner (VarTable), each in a color of its own (graph_view.var_colors: the theme's series without red and grey); no variable boxes or dotted wires any more: the bound parameter rows in the nodes carry the variable's color, a selected variable makes its rows bold. Drag a row onto a node to bind, double-click to edit, right-click for its menu. A node lists the files it reads (its P.Path/P.Paths values) as rows with a document or folder symbol, red when not found. Input ports: filled when connected, dashed when optional and open, red when needed and missing. A legend of these symbols over the bottom right corner (Legend); fit() keeps the graph left of both. Boxes grow to fit their names and sizes (graph_view.box_width: 12 to 26 grid units; each column as wide as its widest box), so nothing is cut (the user, 2026-11-24). After each port's name its dimensions' sizes in muted text ("5 × 201", "(n, m)" before a result; the user chose this over full names and over (n, m) from rendered variants); an output whose variables lie along unrelated dimensions (the rig's records, the power traces) shows none (port_dims: only a variable spanning all the dataset's dimensions counts). Tool tips are the canvas's own (GraphView._show_tip, 350 ms, from the topmost item under the mouse that has one): Qt's waited ~700 ms, and a wire's faint copy over the boxes (and a curve's filled shape) hid the ports' tips; wires now count as under the mouse only along their line. A folder row's tool tip lists the files inside (the node may read any; engine.file_stamp covers them all, so a change to any runs it again). The old `var_pos` in graph files is no longer used.
- **The UV module's nodes** (2026-11-24, the user chose the "cleaner cut"; plots later moved into one view, "Quantum yield" (QuantumYieldView): the old viewer's group of six plots, spectra with the green expected spectrum, absorbance at λ with click-to-ignore, quantum yield, φ₀(λ), Δ spectra, power meter, with the interrupt lines): readers apart from computing (Agilent spectra file, Agilent spectrum file for the buffer, Power meter folder, Nucleoside spectra file), then Spectrum corrections (blank, buffer, baseline, extra, combining), Irradiation steps, Quantum yield and φ0 vs. λ spectrum. Inputs and outputs are named by what the data are (measured_spectra, uncombined_spectra, spectra_with_totals, quantum_yields, phi0_fit, epsilon, rig_records); inputs carry a help text (Signature(help=...)). The sample's numbers (nucleosides, lambda_irradiation, thickness, volume, fit_num) and lambda_spectrum are analysis variables; Quantum yield and φ0(λ) are both bound to them (the old `setup` output that passed them as data is gone). An optional input whose source gives nothing (the buffer reader without a file) is left out, not an error (Engine.prepare). Still bit-identical on all 72 real experiments (2026-11-24). Analyses made with the old nodes do not open with the new ones (no migration; the one test project was made again from the template, λ kept). Plots styled as the kufner viewer's (2026-11-24, the user: "I quite like how the old software looks"): quantum yield in % with blue crosses, a grey dashed fit and a black bar for φ₀ at 0 with φ₀ written in the corner; φ₀(λ) one blue line with a light blue band for the chosen x axis (analysis variable x_axis, energy or time, bound to both); Δ spectra per irradiation time in mOD/s; extra spectra grey dashed; the λ line labelled. Symbol "_" added to the plot protocol for the φ₀ bar.
- **Parameter forms** (2026-11-23, the user: fields as wide as the card were too long): the unit in brackets right after the label ("thickness [mm]", forms.label_text, also for analysis variables in the inspector); numbers and choices about 10 characters wide, ranges, short lists and words 18 (forms.field_chars); these stand side by side in as many aligned columns as fit (ParamForm._fit, re-placed on resize like ReflowGrid). Paths, lists of ranges or points, multi-line text and steps keep a full row.
- **Following changes on disk** (2026-11-24, the user: "not a priority, but nice to have"; planned in a note of the same day): Modules → Follow changes on disk (on by default, remembered) makes the window reload a module whose code changed and compute again the analyses whose files changed, so an LLM's edit of a module or a measurement still being written shows at once. gui/watch.py: one QFileSystemWatcher on the module folders (modules.code_files: what the code hash is made of) and the folders modules are searched in (Registry.bases), and on the data the path parameters of the open analyses name (a folder with every file inside: a directory watch does not see a file written in place; a file with its folder: a save by rename replaces the watched file, and Qt forgets it, so the watched set is rebuilt after every change). Changes are acted on once none came for 500 ms. Nothing else is needed for the data: fingerprints hold the file stamps. A module change does less than Reload modules: Registry.refresh forgets only the imports of modules whose code hash changed, memory is kept, the workers keep running (worker.node_class imports a module again when a task names another version of its code), the cards using the module are rebuilt and every open analysis is requested (links). Two guards keep a result from being stored under the wrong code: a worker checks after importing that the code on disk is the task's (else ModuleChanged: nothing runs, Engine.finish keeps nothing, the runner holds it apart in Runner.stale until the next reload instead of sending it again), and module code is imported without writing .pyc files (Python checks them by size and modification time in whole seconds, so a quick edit of the same size was imported from the old bytecode). The project's tesselab/ folder is never watched for data (the window writes there).
- **Dragging λ is smooth** (2026-11-24, the user: "This is really important, it makes the software usable"; a real-mouse drag on a copy of a project with two real experiments linked, offscreen at scale 1.5, went from ~1700 ms to ~95 ms per step, all measured with real workers): (1) a node whose result is on its way keeps its plots, header text and messages (NodeGroup.draw, update_pending) instead of the note "Computing …", which rebuilt every plot twice per wave (~20 builds per step); the status dot says "running". The rule "an older result is never shown for the new state" still holds for results, not for plots already drawn. (2) Axis labels are set in place (the absorbance plot names λ). (3) A plot's description is kept while nothing it read has changed: DrawContext records what a draw function reads (Reads, snapshot, same_as: inputs by identity, parameters and variables by value; reading out, diagnostics or others makes it uncacheable), NodeGroup.draw keeps (snapshot, spec) per tile, and PlotView.set_spec returns at once for the same description. (4) Engine.bound remembers bind(): the same data bound the same way is the same dataset, which is what makes (3) work for inputs. (5) PanelView._update puts new data into the items of a mark of the same look (UPDATABLE) instead of making them. (6) CursorItem is no scene item: PlotView paints it over its cached picture (moving it did not redraw the plot; the spectra took 10 ms) and takes the mouse for it (grab, hover, drag). Its label is drawn on the side of the line with more room. (7) A step of a dragged cursor is sent only when the last one is computed (AnalysisCard.set_param, _waiting_drag, sent by update_results): before, the workers computed positions nobody saw and the dependent plots froze until the mouse stopped. (8) Engine.stamp remembers file stamps for a second (edits ask the runner with fresh=False; every other request and every Engine.compute read the files again); graph.clone replaces copy.deepcopy for documents; unchanged status, messages and forms are not set again. Tools: a script like `tools/measure_drag.py` but with real mouse events is how this was found (it is not in the repository). Still open: ~60 ms of the step are painting the plots whose data change and the compute chain; plots below the fold are drawn though nobody sees them (drawing only visible tiles would save more).
- **Kept from the kufner viewer** (each measured there): PlotView's picture cache (Wayland, fractional scaling), Shift+wheel zoom and Shift+drag box zoom, matplotlib-like ticks, ReflowGrid arranging itself at once, garbage collection only in the Qt thread, spawn workers with PR_SET_PDEATHSIG.
## Differences from the design document (v3)
- `draw(ctx)` takes one DrawContext (`ctx.out`, `ctx.params`, `ctx.inputs`, `ctx.label`, `ctx.others`) instead of `draw(outputs, settings)`.
- Pick is Ctrl+click (add) and Ctrl+right-click (remove).
- Trust is stored per user, not in project.toml.
- Signature matching: names first, numeric only (see above).
## Testing
- `pytest` (75 tests, ~340 s): `test_core.py` (no Qt), `test_uv_module.py` (bit-identical to kufner_uv_analysis on its sample; skipped where that package is not installed), `test_gui.py` (offscreen; the runner inline, two tests with real worker processes; following module, file and folder changes on disk), `test_examples.py` (both example modules and a new scaffold pass check; the TA fit recovers the synthetic lifetimes; crosshair and pick in the window). conftest.py points the user folders (XDG) to a temporary folder.
- `python tools/compare_uv.py <folder that holds the experiments>`: all real experiments against kufner_uv_analysis, read-only (the author's check).
- `tesselab check examples/modules/uv_photochemistry` (and the other example) and on a fresh `tesselab new module`.
- Look and speed: `python tools/screenshots.py <session> <folder> [1.25]` and `python tools/measure_drag.py <session> [--profile]`; both read only and keep the window's settings in a temporary folder. Show the user rendered screenshots for visual choices.
- A test project from real data: copy experiment folders (read-only source) into a new folder, e.g. `cp -r <experiment folder> <project>/data/`, then open `<project>`: the UV template recognizes them (New data) and takes over their `analysis_params.json`.
- Long runs (the full suite, scripts that open windows) under a memory watch: on 2026-11-22 a runaway test process grew to 25 GB and the kernel's OOM killer closed the Claude app with it (they share a systemd scope). Sample the RSS and kill the PID above ~2.5 GB (`kill -ABRT` makes pytest's faulthandler print the stack); after stopping a background shell, check that its Python child is gone.
- Run everything with one environment's Python, from the repository root: `python -m pytest` (conftest adds src/).
## Releasing
- The version lives in one place, `__version__` in `src/tesselab/__init__.py` (pyproject.toml reads it). The tag is `v<version>`; the workflow refuses a release whose tag differs.
- `.github/workflows/publish.yml` builds the wheel and the source archive, runs `twine check --strict` and uploads with PyPI's trusted publishing (no token is stored anywhere). It never runs on a push: start it by hand (Actions > Publish to PyPI > Run workflow: testpypi or pypi) or publish a GitHub release (uploads to pypi).

## Pitfalls
- Spawned workers re-import the main script: scripts that open analyses need `if __name__ == "__main__":`. `python -m tesselab` is safe (a package's `__main__` is not re-imported).
- Don't name a QWidget method `update` (NodeGroup.show_result): it shadows QWidget.update.
- Renaming dimensions to placeholders can clash with existing dimensions (SVD output has n, m and component): signature.bind renames in two steps.
- A widget just added to a visible layout is shown only later (queued): don't decide by isVisible() whether to draw (NodeGroup used to stay "Computing …" after a node was removed); use the analysis's open state.
- QGraphicsItem draws a dotted frame around a selected item: Box and VarBox paint without State_Selected (their border shows the selection).
- A drag in the graph window that starts before a pending redraw (an edit a moment ago) met boxes of the old state: begin_drag draws first; accepted() lists only nodes that have boxes.
- Widgets added to a card after its header (rebuilt groups) cover the pinned header: rebuild() raises it again.
- Combo boxes size to their longest item: in the narrow inspector they use AdjustToMinimumContentsLengthWithIcon, binding choices one per row.
- QTabBar tells the layout about a new width only while it is visible, and its minimum width (room for scroll buttons) can exceed one short tab: Tabs calls updateGeometry after every change and on show, TabBar caps minimumSizeHint at sizeHint (a gap before +, or no tab at all when a saved window was opened at start).
- `Window.current_tab()` makes a tab when there is none: never call it from a handler of tab changes (closing all tabs then made a new one for each one removed, without end: 25 GB, the OOM killer took the Claude app with it, 2026-11-22).
- Python application event filters (and slots on application signals) must be removed before Python shuts down (atexit; theme.apply, window._detach): Qt filters the events of the widgets PySide deletes at exit, and calling Python then made shiboken allocate memory without end, at every quit (found 2026-11-22 as a 2.8 GB spike after the last test).
- An edit that adds or removes nodes rebuilds the groups of every card before anything else runs (Card.edit): settings or results reaching the group of a removed node raised KeyError, and the group stayed with a grey dot.
- Fingerprints need the inputs' results: never call Engine.fingerprint for a node whose dependencies have no result yet.
- pyqtgraph updates auto range only when painted; render_image shows the view offscreen (WA_DontShowOnScreen) and processes events before rendering.
- A style sheet without a selector, set on a widget, applies to all its children too: the drop-down popup's container got `background: transparent` to show its round corners, and the list inside became see-through. Give such style sheets a selector (`QComboBoxPrivateContainer { ... }`).
- Style sheets need image files for icons (tab close button): theme._icon_file writes them to the user's cache folder.
- Icons are pixmaps in the colors of the theme they were drawn in. Make icon buttons with theme.icon_button: it keeps the icon's name, and theme.recolor_icons draws every such button anew when the theme changes (the card headers kept the light theme's dark grey on the dark page, 2026-11-23). Other icons (group chevrons, the explorer's search icon, the save icon's state) are set again in Window.set_theme. Qt's own icon for a disabled button (the icon greyed) looked like the usable one on the dark page: theme._button_icon draws a faint one.
- pyqtgraph's PColorMeshItem segfaults (the whole process) on a masked array as soon as any cell is masked: Heatmap passes NaN for missing cells (2026-11-22, a TA map shifted out of its data by a chirp pick).
- Plot scenes have no BSP index (PlotView: `NoIndex`): pyqtgraph's AxisItem with a grid counts its view box into its bounding rect, which then changes without prepareGeometryChange when the view box narrows (color bar, pad_right). Qt's BSP index kept the old rect, missed the axis when the plot was rebuilt, and painting read the deleted axis: an intermittent segfault in `QGraphicsScene::items` under `PlotView.paintEvent` (2026-11-23, test_graph_editing, about one full run in four). A plot scene has one top-level item, so the index gained nothing (render and drag times measured equal). To catch use-after-free crashes like this reliably, run with `GLIBC_TUNABLES=glibc.malloc.perturb=165:glibc.malloc.tcache_count=0` (without tcache_count=0 most small frees are not poisoned).
- A plot built anew while a cursor or range is dragged must wait (2026-11-24: the note "Computing …" has no axes, so it is a new layout; the dragged pyqtgraph line was deleted under the mouse and the scene kept sending the drag to it, "Error sending hover exit event", RuntimeError: … already deleted; now cursors are overlays, but a new layout would still read the mouse in the wrong coordinates). PlotView.set_spec holds back a description with a new layout while PlotView.dragging() and draws it after the release (drag_finished, on a 0 ms timer). A layout is what _structure says: axis labels are not part of it (PanelView.set_labels sets them in place). test_a_dragged_cursor_waits_for_a_new_layout.
- Don't connect a lambda to a long-lived object's signal (the runner, the application) from a widget that can be deleted (the graph window): Qt cannot disconnect a lambda, so it calls into the deleted widget at every emit. Connect a method of the widget.
- Closing an analysis with unsaved changes changes what links to it read (the file again): the analyses linking to it are recomputed (Window._request_linking), as after an edit.
- QLineEdit takes Ctrl+Z and the platform's redo key for itself even when it has nothing to undo, and setText empties its history: a value field kept the focus after Enter and swallowed Ctrl+Z. Fields of analysis values are forms.ValueEdit, which lets the keys through to the window when there is no typing to undo.
- PySide ignores monkeypatching QMenu.exec at class level: test menus through a function that builds them (GraphDialog.menu_at) instead of exec.
- QFileSystemWatcher (inotify): a directory watch reports files added, removed and renamed, not a file written in place (that needs a watch on the file); a file replaced by a rename is dropped from the watch list. watch.Follow rebuilds the watched set after every change.
- From the author's earlier viewer: `conda run` does not pass stdin; synthetic wheel events need QTest on the window handle; `deleteLater` needs an event loop.
